# 决策日志（Decision Log）

本技能用于把**关键技术选型、重大路线调整、刻意舍弃的特性以及反向避坑约束**以极简但硬核的格式（D-XXX）实时落盘。

它绝不依赖沉重的第三方工作流引擎，完全由本地 Markdown 单文件驱动，杜绝后续重构时的重复讨论与认知回退。

## 核心设计：为什么这样记？

1. **避免文档膨胀与重复沟通**：每个项目一个 `decisions.md`（或 `decision_log.md`），采用递增追加模式。
2. **反向约束最优先**：最核心的一段是「**影响 / 必须知道的事：不要再把以下现象当缺陷修**」，写清哪些边界是故意裁剪的，防止 AI 或后续开发反复把预期行为当 Bug 修。
3. **只记关键分水岭**：日常琐碎编码不记；路线二选一、推翻方案、避坑重构、评测口径变更才记。

## 工具与标准流

### 1. 查阅与检索既有决策（防重读全文）

在决定做某件事之前，先快速查看当前项目或课题目录下有哪些已定结论：

```bash
pwsh.exe -NoProfile -File <SKILL_DIR>/scripts/list_decisions.ps1 -Root <项目路径> [-Filter <关键词>]
```

- 脚本只提取标题行，以极简表格输出，绝不把几十 KB 全文打进 Prompt。
- 发现相关决策后再针对性读取对应段落。

### 2. 准备追加新决策

第一步：调用编号计算器，获取下一个合法 ID 与确切落盘文件路径：

```bash
pwsh.exe -NoProfile -File <SKILL_DIR>/scripts/next_decision_id.ps1 -Root <项目路径>
```

返回标准 JSON：
```json
{ "ok": true, "file": "D:\...\decisions.md", "next_id": "D-004", "existing": 3, "created": false }
```

- 优先复用当前目录或 `docs/` 下已有的 `decisions.md` / `decision_log.md`；若无则自动定位在项目根下新建。

### 3. 落盘写入决策条目

使用 `write`（初次建文件）或 `edit`（在文件末尾追加），格式严格遵守三段式：

```markdown
## D-XXX（YYYY-MM-DD）一句话决策标题

**决策**：明确说明项目决定**做什么**或**不做什么**。句子果断明确。

**Why**：
- **背景与约束**：面临什么硬件、算力、截稿时间或资源限制？
- **对比权衡**：为什么选 A 不选 B？优缺点与成本对比。

**影响 / 必须知道的事**：
1. **反向约束（极关键）**：明确「不要再把以下现象当缺陷修」或「后续绝对不能踩的坑」。
2. **协同与接口影响**：上下游数据结构、参数或调用方式的变更说明。
3. **预期验证指标**：本次决策预期达到的量化指标（如延迟从 50ms 降至 15ms）。
```

若当前决策是为了**推翻或替换旧决策**，在标题下方第一行醒目标注：
`> ⚠️ **状态变动**：推翻历史决策 D-YYY，由本决策完全取代。`
